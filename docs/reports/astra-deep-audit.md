# Astra implementation audit

13 September 2026 | Supersedes readiness claims in `gpt-astra-handoff.md`

## Verdict

The product direction is coherent: record early opportunities, distinguish actual demand from ambiguous receipts, evaluate executable follower outcomes, and test whether fly-derived recurrence adds value. The implementation is a collection of useful, mostly isolated research components. It is not an operational Observatory or a validated shadow platform. A frozen config and passing unit tests are not sufficient to start a credible prospective strategy study.

The incoming handoff accurately listed missing live history, connectome provenance, LP evidence and observation duration. It overstated implementation completion by calling fixture-covered slices DONE despite unmet acceptance criteria and prerequisites. The largest issue is integration: capture/backfill CLI handlers construct plans, the server receives an empty in-memory store, the HTML renderer is not routed, and shadow does not consume collector output. No captured-data-to-decision demonstration exists.

## Review method and limits

Read the handoff and implementation log, inspect ingestion/storage, identity and attribution, projections/API/UI, replay/labels/splits, model fitting/packaging, optional LLM boundaries, LP and shadow code. Run the existing suite, exercise adversarial inputs absent from it, add targeted regressions, and run the expanded suite. This is a source and local-behavior audit; no live 72-hour collection, 14-day shadow study, funded execution, provider SLA or full scientific validation was performed. Existing bounded live-probe claims were read, not independently re-established here.

Incoming suite: 81 passed. After corrections: 100 passed, including 19 additional adversarial cases. Existing tests for split-boundary leakage, fabricated text spans, planning-only CLI returns, wrong-direction exit quotes and phantom cash release were corrected to assert intended behavior. Full-suite success does not clear the open findings below.

## Findings and disposition

| ID | Severity | Finding, impact and disposition |
|---|---|---|
| F01 | High | **CLI/runtime integration absent.** `cli.py` plans capture/backfill and starts an empty store; shadow only validates configuration. Fixed misleading success: capture/backfill now return `plan_only`, `executed=false`, exit 3; frozen shadow remains blocked with `shadow_runtime_not_integrated`. Actual orchestration remains open. |
| F02 | High | **Raw republish could corrupt its own checksum.** Gzip inherited the random temporary filename, then republishing replaced bytes before discovering the existing DB row. Fixed: verify/reuse existing batches, omit filename from gzip header, retain acknowledgement. Dot partitions and invalid dates are rejected. Crash-safe directory synchronization, empty-range acknowledgement and writer serialization remain integration work. |
| F03 | High | **Missing event time was replaced by arrival time.** Historical rows could appear current and falsely show zero arrival delay. Fixed capture/backfill to resolve missing/zero times through a hash-matched block header or fail without acknowledgement. Backfill now checks chain before logs; one-shot capture is bounded to 2,000 blocks. Existing captures with fallback timestamps must be reprocessed from header evidence or marked unavailable. |
| F04 | High | **Fork recovery lacks complete headers.** Captured parent hashes are null; canonicalization derives headers only from matching events, so quiet blocks and missing parents cannot be resolved reliably. Non-tip records may be incorrectly orphaned. Persistent full header ancestry and transactional projection rollback remain open. |
| F05 | High | **Backfill checkpoints are not tied to durable evidence or filter identity.** Callbacks are optional, source names key checkpoints, and returned events accumulate in memory. A changed address set can resume a prior scan; progress can persist without raw bytes. Require durable range acknowledgements keyed by chain/filter/ABI plus block evidence. Open. |
| F06 | High | **Swap attribution is insufficient proof.** Any matching-transaction swap plus wallet payment/receipt can become `genuine_swap`; the code does not prove the received token belongs to that route or account for all refunds. Initialize issuer validation is delegated to callers. Timelines do not deduplicate TradeEvidence or calculate sells/net flow. Unrelated multicall transfers can inflate demand. Open; treat current verified-flow metrics as provisional. |
| F07 | High | **Timezone-string sorting and split leakage.** Replay could block an earlier event behind a lexically smaller later one. Training labels could extend into validation while validation rows were removed instead. Fixed instant-based replay/split ordering, event/availability ordering, unique split names and purging labels beyond their own partition. Other projection/cohort sorting and lifecycle as-of reconstruction still need review. |
| F08 | High | **Shadow proposals fabricated liquidity.** Exit decisions released original entry allocation regardless of modeled proceeds. Fixed: exit proposals remain hold/reconcile until a modeled execution ledger is integrated. Future observations and out-of-order new arrivals are rejected; duplicate replay no longer rewinds checkpoints; asset participates in decision identity. Run/config binding, durable token inventory and atomic decision/ledger/checkpoint writes remain open. |
| F09 | High | **Frozen-config contents were not checked.** Any non-empty hash passed the CLI readiness check. Fixed hash recomputation and atomic file replacement during freeze. Hashes must eventually include source, model, feature and dataset dependencies; existing DB state must bind to one frozen run. Open integration work. |
| F10 | High | **Execution is a toy constant-product path.** It does not implement V4 concentrated liquidity, fee/hook mechanics, state-at-fill selection, gas asset accounting or receipt-level cost reconciliation. Future quotes and mismatched round-trip asset directions now fail safely. Approximate replay remains unsuitable for profitability labels; the protocol engine and complete ledger bridge are open. |
| F11 | High | **Forward labels do not implement the declared fixed-horizon task.** An episode exiting before a horizon is reused for later horizons; failed/unsellable outcomes collapse to unresolved. Rebuild labels from a feasible entry and liquidation attempt at each declared horizon with explicit censorship, failure and inventory valuation. Open. |
| F12 | High | **Financial evaluation is not portfolio evaluation.** Drawdown adds episode return basis points; walk-forward repeats the same records for every cost/capital setting; audit accepts counts supplied by the caller. Walk-forward and replay bundle eligibility no longer claim successful validation. Equity curves, scenario reruns and evidence-derived audits remain open. |
| F13 | High | **Linear/readout fitting ignored feature covariance.** Independent feature slopes are not joint ridge regression. Fixed with a common centered joint ridge solver, unpenalized intercept, finite-input and singularity checks. It is suitable for small fixtures; use a verified QR/SVD solver and conditioning tests for large experiments. Ordinary recurrent baseline is still a scalar fixed recurrence, insufficient as the sole strong comparator. |
| F14 | High | **Neural gate could pass with only a fly model and caller booleans.** Fixed to remain inconclusive until actual portfolio evidence is validated. Biological provenance, controls, unique seeds per model, drawdown gates, four locked windows and correctly computed paired intervals remain unimplemented. Graph orientation metadata is not applied to edge dynamics; graph validation permits problematic weights. Open. |
| F15 | Medium | **Package validation trusted incomplete metadata.** Empty file hashes bypassed integrity checks, and actual graph content was not matched to the readout. Fixed exact required file set and computed graph-hash consistency. This is integrity checking, not authentication of an external publisher. |
| F16 | High | **LP accounting is dimensionally invalid.** A remove event can credit assets without an opened position; collection sums quantities of two different tokens; gas is tallied without debiting its asset; linear tick amounts are not V4 liquidity math. Inside-fee growth should account for accrual since last update even after the position leaves range and handle modular arithmetic. Open; keep LP disabled and prohibit interpreting these balances as economic results. |
| F17 | High | **LLM bounds and evidence are incomplete.** A callback can block indefinitely; whitespace counts are not provider tokens, and budgets reset per call/retry. Unsupported claim types and invented literal evidence now trigger fallback. Persistent budgets, transport deadlines, usage reconciliation, full schema/field restrictions and cache provenance remain open. |
| F18 | Medium | **Heterogeneous Parquet export changed or lost fields.** Arrow inference could discard later-only keys, insert nulls, or overflow large integers. Fixed lossless canonical JSON records in an explicitly declared Parquet encoding. Legacy exports remain readable. Typed analytical columns, atomic export manifests and scalable content indexes are later work. |
| F19 | Medium | **Coverage and publication readiness were overstated.** Empty reference sets passed coverage; DONE statuses represented partial slices. Empty-reference audits now degrade, task statuses are re-audited with preserved prior evidence, temporary datasets/renderings are ignored, and CI plus a non-resetting task renderer/checker are added. No software license is invented for private project publication. |

## Reproduction anchors

`tests/test_audit_regressions.py` covers republishing/acknowledgement, corrupt evidence, partition validation, heterogeneous/big-integer export, mixed timezones, ridge covariance/intercepts, missing package hashes, config tampering, future shadow observations, empty coverage, wrong-chain backfill, bounded capture/header timestamps, quote causality/asset directions, false neural eligibility and unsupported LLM claims. Existing `test_shadow.py` verifies that unknown exit proceeds cannot free allocation and duplicate restart cannot rewind progress.

Additional source-level probes confirmed remaining issues: `replay_lp_lifecycle([LPEvent('x','remove',100,100,source_ref='test')], token0='A', token1='B')` credits both assets with no initial position. `calculate_metrics` over two -5,000 bps episodes reports 10,000 bps drawdown from summation, although those episode returns do not define a portfolio equity curve. The same supplied episodes produce identical walk-forward metrics under different registered fees and delays. These are release blockers, not accepted financial assumptions.

Protocol checks used primary sources: [Uniswap V4 Position](https://raw.githubusercontent.com/Uniswap/v4-core/main/src/libraries/Position.sol), [Uniswap V4 SqrtPriceMath](https://raw.githubusercontent.com/Uniswap/v4-core/main/src/libraries/SqrtPriceMath.sol). They support the fee-growth and price/liquidity requirements; their current main branch is not evidence of the Robinhood deployment revision. Implementation must pin deployed bytecode/ABI. The [ridge objective](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html) and [Python gzip documentation](https://docs.python.org/3/library/gzip.html) support the corresponding corrections.

## Decision and next build

Proceed with the idea and reuse the tested pieces. Do not begin the formal shadow performance window merely by freezing the current config. First complete an integrated, read-only recorder with a populated inspection interface and demonstrable restart recovery. Gather observation evidence separately from later strategy qualification. Then implement economically valid replay, labels and portfolio metrics; only then compare neural architectures and optional signals. See [next roadmap](../next-build-roadmap.md), [next JSON backlog](../next-build-tasks.json) and [Muse Sparks 1.3 handoff](../muse-sparks-1.3-handoff.md).

The user authorized commit/push to a new private repository and preparation for Muse Sparks 1.3. This audit does not switch the running model, create a new model session, start funded activity, buy data access or enable automatic capital allocation.
