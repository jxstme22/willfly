# Observatory v0.1 demo checklist

This checklist distinguishes offline/synthetic verification from live evidence.
It does not authorize a signer, transaction broadcast, subscription purchase or
funded trading.

1. Run `python -m willfly doctor` and confirm chain ID `4663`, read-only mode and
   the open launch-source gate.
2. Start the future recorder against the selected launch source and V4 pools;
   show checkpoints and arrival-delay histograms. Until P0/P1 access gates pass,
   use the explicitly labeled fixture run.
3. Open one launch that later has a pool and one launch with no observed pool.
   Keep creation, first-seen and unknown history separate.
4. Inspect a V4 pool timeline with manager plus Pool ID, token identifiers,
   swaps, liquidity changes, source timestamps, arrival timestamps and raw refs.
5. Stop, replay an overlapping backfill and restart. Logical keys remain stable
   and lineage is retained.
6. Run fixture checks for duplicate delivery, fork/orphan evidence, provider
   disconnect, malformed logs, native ETH and a receipt with no payment leg.
7. Export a dataset with schema/config/source hashes, coverage audit, gaps and
   missingness. A second local process reproduces logical records.

## Current gate report

The offline contract and fixture checks are runnable. Native RPC identity, V4
deployment evidence and a bounded live sample for all three supported V4 event
families are recorded. The launch-level v0.1 gate is open because Pons V2 ABI,
creation coverage and archive history remain unverified. No live 72-hour recall
or 15-second latency claim exists.
